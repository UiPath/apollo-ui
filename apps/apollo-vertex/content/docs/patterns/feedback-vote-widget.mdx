A thumbs up / thumbs down control with an optional comment textarea, designed to capture user sentiment on AI-generated content.

## Features

- **Two-state vote** — Thumbs up / down, with `aria-pressed` reflecting the current selection
- **Optional comment** — Toggle a textarea below the vote buttons for free-form feedback
- **Controlled** — Pass `value` + `onVoteChange` (and `comment` + `onCommentChange` when `showComment` is true)
- **Accessible labels are required** — `upLabel` / `downLabel` (and `commentPlaceholder` when applicable) must be provided so consumers can plug in their own translated strings
- **Sizes** — `default` and `sm`
- **Composes existing primitives** — Built on [Button](/components/button) and [Textarea](/components/textarea)
- **Test hook** — Each vote button carries `data-vote="up"` / `data-vote="down"` for E2E selectors

## Usage

### Basic

```tsx
import * as React from "react";
import { FeedbackVoteWidget } from "@uipath/apollo-vertex";

export function MyFeedback() {
  const [vote, setVote] = React.useState<"up" | "down" | null>(null);
  return (
    <FeedbackVoteWidget
      value={vote}
      onVoteChange={setVote}
      upLabel="Vote up"
      downLabel="Vote down"
    />
  );
}
```

The labels above are inline strings for clarity — in a real app source them from your i18n library (`t("feedback.voteUp")` etc.) so the widget reflects the user's locale.

### With comment

```tsx
const [vote, setVote] = React.useState<"up" | "down" | null>(null);
const [comment, setComment] = React.useState("");

<FeedbackVoteWidget
  value={vote}
  onVoteChange={setVote}
  upLabel="Vote up"
  downLabel="Vote down"
  showComment
  comment={comment}
  onCommentChange={setComment}
  commentPlaceholder="What could the AI have done better?"
/>
```

When `showComment` is `true`, `comment`, `onCommentChange`, and `commentPlaceholder` become required (enforced via the props' discriminated union). When omitted or `false`, the comment-related props can't be passed at all — the type system prevents inconsistent states.

### Wiring to VSS feedback

The widget only renders the vote; your app submits it with `@uipath/vs-feedback` 5.0.0 or later ([README](https://github.com/UiPath/vertical-solutions/blob/main/packages/feedback/README.md)), which writes through the VSS feedback service.

**1. Declare the feedback type.** Keep every feedback type in one module that exports `solutionId` and `feedbackTypes`. The schema check reads this module, and every client is built from its exports.

```ts
import { defineFeedbackType } from "@uipath/vs-feedback";

type VoteMetadata = { itemId: string };
type VoteComment = { text?: string };

// Your solution package GUID (SolutionId in the solution's SolutionStorage.json).
export const solutionId = "00000000-0000-0000-0000-000000000000";

export const answerVote = defineFeedbackType<VoteMetadata, VoteComment>()({
  name: "my-vertical-answer-vote",
  metadataSchemaVersion: "1.0.0",
  commentSchemaVersion: "1.0.0",
});

export const feedbackTypes = [answerVote] as const;
```

**2. Build the client from those exports.**

```ts
import { PlatformFeedbackClient } from "@uipath/vs-feedback";

import { feedbackTypes, solutionId } from "./feedbackTypes";

export function createFeedbackClient(platform: {
  baseUrl: string; // e.g. https://cloud.uipath.com
  orgName: string;
  tenantName: string;
  orgId: string;
  tenantId: string;
  folderKey: string; // the deployment's Orchestrator folder
  getAuthToken: () => Promise<string>;
}) {
  return new PlatformFeedbackClient({
    solutionId,
    solutionName: "My Vertical",
    feedbackTypes,
    ...platform,
  });
}
```

**3. Submit the vote.** The widget's `value` becomes `isPositive` and its `comment` goes into the comment schema you declared. `traceId` is required: use the trace id your app stored next to the agent output. Pass `agentId` and VSS tries to fill in the span and agent version from that run; if it can't, the write goes ahead without them.

```ts
import type { createFeedbackClient } from "./feedbackClient";

type FeedbackClient = ReturnType<typeof createFeedbackClient>;

export async function submitVote(
  client: FeedbackClient,
  args: {
    vote: "up" | "down";
    comment: string;
    traceId: string;
    agentId: string;
    itemId: string;
  },
) {
  await client.submit({
    feedbackType: "my-vertical-answer-vote",
    traceId: args.traceId,
    agentId: args.agentId,
    isPositive: args.vote === "up",
    metadata: { itemId: args.itemId },
    comment: args.comment ? { text: args.comment } : {},
  });
}
```

### Before you release

- **Register the schema versions in VSS first.** A write is accepted only when its solution, feedback type and schema versions are registered. Open a registry PR in `vertical-solution-service` under `packages/feedback/src/registry/<vertical>/`, and get it deployed to production before you ship the app that declares those versions. See the [registry README](https://github.com/UiPath/vertical-solution-service/blob/main/packages/feedback/src/registry/README.md).
- **Dev tenants are lenient; customer tenants are not.** In a dev tenant, an unregistered version is accepted, the row is stamped `isDev: true` and the response carries `validation: "unregistered"`. A customer tenant rejects the same write with a 400.
- **Turn on the schema checks.** With `@uipath/vs-feedback` 6.0.0 or later, `vs-feedback declared-versions` lists the versions your types module declares, and two opt-in checks compare them with VSS, so a missing registration fails the PR or the release instead of a customer's first write. For PRs, call the shared [`vertical-solutions-check-feedback-schemas`](https://github.com/UiPath/.github/blob/master/.github/workflows/vertical-solutions-check-feedback-schemas.yml) workflow; its header lists the per-repo identity setup it needs. For releases, add [`write-declared-versions`](https://github.com/UiPath/vertical-solutions-tools/blob/main/cicd/steps/write-declared-versions.steps.yml) to the build and [`check-feedback-schemas`](https://github.com/UiPath/vertical-solutions-tools/blob/main/cicd/steps/check-feedback-schemas.steps.yml) to each deploy stage. The deploy check reads the artifact the build step publishes, so add both. The [cicd README](https://github.com/UiPath/vertical-solutions-tools/blob/main/cicd/README.md#declaring-and-checking-feedback-schema-versions) covers the deploy setup, and the SDK README section [Declaring feedback types for the schema check](https://github.com/UiPath/vertical-solutions/blob/main/packages/feedback/README.md#declaring-feedback-types-for-the-schema-check) covers what your types module must export.
- **Read more:** the [tech spec](https://uipath.atlassian.net/wiki/spaces/VA/pages/91090157583/Feedback+capture+via+VSS+-+tech+spec) and the [`@uipath/vs-feedback` README](https://github.com/UiPath/vertical-solutions/blob/main/packages/feedback/README.md).

## API Reference

| Prop | Type | Required | Default | Description |
|------|------|----------|---------|-------------|
| `value` | `"up" \| "down" \| null` | yes | — | Current vote state. `null` = no vote yet. |
| `onVoteChange` | `(vote: "up" \| "down") => void` | yes | — | Called when a vote button is clicked |
| `upLabel` | `string` | yes | — | Accessible label for the up-vote button (translated) |
| `downLabel` | `string` | yes | — | Accessible label for the down-vote button (translated) |
| `showComment` | `boolean` | no | `false` | Render the comment textarea below the buttons |
| `comment` | `string` | when `showComment` | — | Textarea value (controlled) |
| `onCommentChange` | `(value: string) => void` | when `showComment` | — | Called when the textarea changes |
| `commentPlaceholder` | `string` | when `showComment` | — | Placeholder for the textarea (translated) |
| `disabled` | `boolean` | no | `false` | Disables vote buttons and the textarea |
| `size` | `"default" \| "sm"` | no | `"default"` | Visual size of the vote buttons |

The widget owns its layout and does not accept `className` or other div props — wrap it in your own container if you need to position it.
